2

Direct todo: each function updates DOM itself

This version does not have one render function that clears and rebuilds everything. Each action directly touches the DOM node it cares about.

3

Functional composition: input in, output returned

Before state, hooks, or DOM, a component idea is just function composition. Data goes in. A view description comes out.


          

        

        

      


      

        

          4
          
The same composition in Reactsim

          
Reactsim components return virtual DOM objects with `createElement()`. The runtime diffs the desired tree and `domRenderer` commits real DOM.

          

        

        

      


      

        

          5
          
Props + private state decide component output

          
A function processes input props plus remembered hook state, then returns output. If props or state change, the component function runs again and returns new output.

          

        

        

      


      

        

          6
          
Reactsim todo keeps list state

          
The todo list lives in `useState`. Adding an item updates state, reruns the component functions, diffs the new desired list, and commits only the needed DOM work.

          

        

        

      


      

        

          7
          
Effects are for external systems

          
Component functions should mostly process input plus state and return output. `useEffect` is the special place for side effects like document title, localStorage, or API calls.

          

        

        

      


      

        

          8
          
Full todo initialized and persisted with localStorage

          
This combines lazy state initialization and an effect. Initial state reads localStorage once. After every todo change, the effect writes the latest list back.
